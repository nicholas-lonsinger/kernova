# Changelog

Every Kernova release, newest first; the top section is the release in progress. Each release opens with Action required: what users of the previous release must do after updating, or lose what they had. Changes that only behave differently are listed under their area.

## 0.11.0

In progress since 2026-09-16: everything since 0.10.0 (TestFlight build 835). This is what testers get when they update.

### Action required

- **macOS guests: reinstall the guest agent.** The old agent no longer connects. In each macOS VM, choose Virtual Machine ▸ Install Guest Agent… and run install.command, which asks whether to install it "Just for me" or "For everyone".
- **macOS guests: delete the old agent app yourself.** The new agent replaces the old agent's background job but leaves the old app at `~/Applications/Kernova Guest Agent.app` in the guest user's home. Nothing launches it any more, and Kernova does not remove it; drag it to the Trash inside the guest.
- **VMs on the Shared network can't be read until you repair them.** The Shared network mode is now called NAT, and Kernova doesn't read the old name from a VM's settings file, so every VM that used Shared appears in the sidebar as a dimmed row that can't be read. Shared was 0.10.0's default, so this is most VMs made with 0.10.0.
  Choose File ▸ Check Config Files… and repair each one with Use Defaults, which sets it to NAT, the same network under its new name. The check can't repair a snapshot taken while the VM was on Shared: delete that snapshot, or change `"networkMode" : "shared"` to `"nat"` in its `config.json` inside the VM's bundle. Scripts that set or compare `shared` must use `nat` ([#1517](https://github.com/nicholas-lonsinger/kernova/pull/1517)).
- **Some per-VM settings start over.** Start when Kernova opens, Ephemeral Mode and its baseline, where the display opens, and a dismissed guest agent install reminder now live in a file that snapshot reverts don't touch, and the values 0.10.0 saved aren't carried over. Turn Start when Kernova opens and Ephemeral Mode back on, and pick the baseline again, for each VM that used them, and set the display placement again where you had changed it ([#1363](https://github.com/nicholas-lonsinger/kernova/pull/1363)).
- **Port forwarding is gone, and guest addresses are no longer reserved.** NAT and Host Only networks are now plain macOS networks on a subnet the system picks, so a guest's address can change between launches. Port forwarding rules, the Network panel's port forwarding section and `kernova forward` no longer exist.
  Reach a guest at the address Kernova shows (`kernova ip`, the Overview or the Network panel) or use Bridged with a reservation on your router, and remove `kernova forward` from scripts ([#1335](https://github.com/nicholas-lonsinger/kernova/pull/1335)).
- **Duplicate machine IDs: you may be asked at each start.** If you had turned off blocking duplicate machine IDs, starting, resuming or restarting a VM beside another with the same machine ID now asks first, quoting Apple's warning. Choose Don't ask again, or turn the question off in Settings ▸ Reminders; until then, Start when Kernova opens and scripts without consent are refused ([#1468](https://github.com/nicholas-lonsinger/kernova/pull/1468), [#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831), [#1838](https://github.com/nicholas-lonsinger/kernova/pull/1838)).
- **Scripts: stop and restart methods are renamed.** `kernova stop --graceful` is now `--normal` and `--resume-first` is gone; AppleScript's `by shut down` and `by force` are now `method normal` and `method force`, and `by resume then shut down` is gone, with no old term kept. Pick the Stop Method again in saved Shortcuts that used Shut Down or Resume then Shut Down.
  Stopping a paused VM from a script is now refused, so resume it first (`kernova resume`) ([#1565](https://github.com/nicholas-lonsinger/kernova/pull/1565), [#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831), [#1838](https://github.com/nicholas-lonsinger/kernova/pull/1838)).
- **Scripts: a snapshot revert no longer takes a snapshot first.** In 0.10.0, `kernova snapshot revert` and the Revert to Snapshot shortcut saved the current state first by default, so a revert could be undone; now everything since the snapshot is discarded. Add `kernova snapshot take` or a Take Snapshot action before a revert you may want to undo, remove `--checkpoint` and `--no-checkpoint`, and re-save Shortcuts that set Take Snapshot First. The app's Take Snapshot, Then Revert is unchanged ([#1565](https://github.com/nicholas-lonsinger/kernova/pull/1565)).
- **Scripts: clone options are renamed, and an Exact Copy keeps the MAC address.** `kernova clone --keep-identity` is now `--exact-copy` and `--new-identity` is `--new-machine`; the Clone shortcut's Machine Identity parameter is now As, so set it again in saved shortcuts. A copy that keeps its source's machine identity now keeps its MAC address too, so it can't run beside its source on the same network; give it a new address in its Network settings to run both ([#1417](https://github.com/nicholas-lonsinger/kernova/pull/1417), [#1466](https://github.com/nicholas-lonsinger/kernova/pull/1466)).
- **Scripts: disk size is replaced by a list of disks.** AppleScript's `disk size`, `diskSizeInGB` in `kernova info --format json` and the Shortcuts property Disk Size in Gigabytes are gone. Read a `virtual machine`'s `storage disks` (for example `capacity of storage disk 1`), `storageDisks` in the JSON, or the Find Disks action instead ([#1641](https://github.com/nicholas-lonsinger/kernova/pull/1641)).
- **Scripts: some reported values changed.** A suspended VM reports `suspended`, not `paused`. A VM with no running session has no guest agent status: `agentStatus` is absent from JSON, AppleScript's `agent status` is missing value, and it is no longer `waiting`. A guest's IP address state reads `observed` or `notObserved`; `kernova snapshot list` JSON has `sizeBytes` and `privateBytes` in place of `onDiskBytes`;
  `editableWhileRunning` in `kernova get --keys --format json` is an object keyed by guest OS; and turning on Ephemeral Mode for a VM with no snapshot exits 5, not 2. Update scripts that test these ([#1335](https://github.com/nicholas-lonsinger/kernova/pull/1335), [#1412](https://github.com/nicholas-lonsinger/kernova/pull/1412), [#1443](https://github.com/nicholas-lonsinger/kernova/pull/1443), [#1469](https://github.com/nicholas-lonsinger/kernova/pull/1469), [#1553](https://github.com/nicholas-lonsinger/kernova/pull/1553), [#1619](https://github.com/nicholas-lonsinger/kernova/pull/1619)).
- **Scripts: turning on Ephemeral Mode needs consent.** Turning it on or changing its baseline from `kernova`, AppleScript or Shortcuts now asks first; pass `--yes` or `with confirmation`, or turn off the action's Confirm Before ([#1664](https://github.com/nicholas-lonsinger/kernova/pull/1664), [#1903](https://github.com/nicholas-lonsinger/kernova/pull/1903)).

### Security

- **Clipboard sharing can no longer point a Mac app at one of your files.** A guest could put content on the Mac clipboard that a Mac app, on paste, resolves to a file on your Mac rather than to the guest's own data: file URLs in disguised spellings, aliases and bookmarks, and rich text whose attachments link to a Mac path.
  The clipboard now refuses all of these, for clipboard sharing and Copy to Mac alike ([#1812](https://github.com/nicholas-lonsinger/kernova/pull/1812), [#1813](https://github.com/nicholas-lonsinger/kernova/pull/1813); release tracked in [#1818](https://github.com/nicholas-lonsinger/kernova/issues/1818)).
- **Guest log values marked private stay private on the Mac.** Records the guest agent forwards keep their privacy marks, so the Mac's log hides those values as it does its own instead of storing them in plain text ([#1254](https://github.com/nicholas-lonsinger/kernova/pull/1254)).

### Guest agent

- **macOS guests: install the agent "Just for me" or "For everyone".** install.command asks which. "For everyone" installs it for every user of the guest, plus a system service.
- **macOS guests: the agent updates itself.** When Kernova bundles a newer agent, the agent installs it in place and relaunches; an update that never confirms rolls back on its own ([#1810](https://github.com/nicholas-lonsinger/kernova/pull/1810)).
- **macOS guests: an agent that can't update itself says why.** An agent installed from a build with a different signature turns the bundled update down instead of being stopped by macOS when it relaunches, and stays on its own version. The VM's agent badge then reads "Guest agent can't update in place", says why, and offers Reinstall Guest Agent… ([#1859](https://github.com/nicholas-lonsinger/kernova/pull/1859)).
- **Virtual Machine ▸ Guest Agent Status.** A window per VM shows what the sidebar's agent badge shows, including which agent handles Stop and Restart and which handles Stop Anyway and Restart Anyway, and why one is unavailable. It's available whenever the running VM has an agent connection, even while the badge is hidden ([#1773](https://github.com/nicholas-lonsinger/kernova/pull/1773), [#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831)).
- **The agent badge appears only when something needs you.** The sidebar's agent badge hides while the agent is current or connected, for every guest OS, and an agent that stops answering reads "Not responding". Each agent, session or system, gets its own grace period before a "didn't reconnect" warning with Reinstall, and a macOS agent that already connected this session no longer triggers it ([#1748](https://github.com/nicholas-lonsinger/kernova/pull/1748), [#1774](https://github.com/nicholas-lonsinger/kernova/pull/1774)).
- **A guest agent that leaves and doesn't come back reads "disconnected".** When a session agent that connected disconnects and stays away for two minutes, for example after you uninstall it or log out of the guest, the VM's agent status reads "Guest agent disconnected" with Install Guest Agent… instead of staying on "Connecting to guest agent" ([#1871](https://github.com/nicholas-lonsinger/kernova/pull/1871)).
- **`kernova info` lists each connected guest agent.** Under Guest Agent it prints a line per agent, such as `Session agent — pbear: current, 0.10.0 (1143)`, and its JSON gains an `agents` array ([#1748](https://github.com/nicholas-lonsinger/kernova/pull/1748)).
- **The installer disk waits for every agent you chose.** It ejects only once each one has connected, and opening it from Manage Guest Agent… no longer ejects it on its own ([#1777](https://github.com/nicholas-lonsinger/kernova/issues/1777)).
- **macOS guests: the installer disk ejects after a "For everyone" install too.** It used to stay attached until the VM stopped, and the session agent read "Version …" instead of "Up to date". The "Installer Mounted" alert now closes on its own once its disk is ejected, whether the agents connected, you ejected it, or the VM stopped ([#1877](https://github.com/nicholas-lonsinger/kernova/pull/1877)).
- **The installer disk a VM has attached is its own copy.** It's kept in the VM's bundle while attached, so a suspended VM resumes onto the same disk whichever Kernova version resumes it ([#1748](https://github.com/nicholas-lonsinger/kernova/pull/1748)).
- **macOS guests: the agent's menu bar shows the connection that matters.** The agent's icon and its "Connected to host" line now follow the connection that carries the clipboard, drag and drop, logs, Stop and Restart, and updates, and Status ▸ Log Forwarding shows whether the agent is forwarding right now. The progress ring that showed on the agent's icon during a paste is gone; it showed nothing since the clipboard moved to the new agent ([#1863](https://github.com/nicholas-lonsinger/kernova/pull/1863)).
- **Every guest agent log record reaches the Mac.** With log forwarding on, the agent's connection and policy messages and its menu bar faults now appear in the Mac's log too ([#1243](https://github.com/nicholas-lonsinger/kernova/pull/1243)).
- **Guest agent controls agree everywhere.** The Virtual Machine menu and the agent popover show the same installer disk command, update when the disk is attached or ejected, and offer it, and the install reminder's Don't show again, only when the VM's state allows ([#1501](https://github.com/nicholas-lonsinger/kernova/pull/1501), [#1619](https://github.com/nicholas-lonsinger/kernova/pull/1619)).

### Clipboard

- **macOS guests: Copy to Mac and Copy to Guest replace the Clipboard window.** Edit ▸ Copy Guest Clipboard to Mac and Copy Mac Clipboard to Guest, also toolbar buttons, copy one clipboard to the other with everything on it, and Edit ▸ Automatic Clipboard Passthrough keeps the two in step. Files and folders cross when you paste them, so an iCloud file stays in the cloud until then.
  When the VM stops, its user logs out or passthrough goes off, what you already pasted stays, a copied file that can no longer be pasted leaves the clipboard whole, and anything marked as a password goes ([#1819](https://github.com/nicholas-lonsinger/kernova/pull/1819)).
- **The clipboard shortcuts work in a VM's screen.** ⌃⇧⌘C (Copy Guest Clipboard to Mac) and ⌃⇧⌘V (Copy Mac Clipboard to Guest) now act while the guest has the keyboard, whatever its system-keys setting, and the guest no longer receives them. Settings ▸ Keyboard lists both; turning one off removes it from the menu and gives those keys back to the guest ([#1840](https://github.com/nicholas-lonsinger/kernova/pull/1840)).
- **Copied passwords follow their source.** A password sent with Copy Guest Clipboard to Mac or Copy Mac Clipboard to Guest leaves the other side when the source's clipboard moves on, for example when a password manager clears it, and when the VM's link ends, whether or not it was pasted ([#1852](https://github.com/nicholas-lonsinger/kernova/pull/1852)).
- **Passthrough carries only new copies.** Turning Automatic Clipboard Passthrough on, the guest reconnecting and Kernova launching send nothing; the next copy on either side is the first to cross, so a stale copy from before raises no error ([#1680](https://github.com/nicholas-lonsinger/kernova/pull/1680), [#1819](https://github.com/nicholas-lonsinger/kernova/pull/1819)).
- **A file that can't be opened is left out of a copy, and the notice says so.** Copy to Mac and Copy to Guest send such a file through its file promise when it has one, otherwise leave it out and say how many items weren't copied; a refusal says "copied" or "dropped" to match what you did ([#1677](https://github.com/nicholas-lonsinger/kernova/pull/1677), [#1819](https://github.com/nicholas-lonsinger/kernova/pull/1819)).
- **Transfer progress appears as a callout.** A paste or drop that takes more than a second shows its progress as a callout from the menu bar item, on the Mac and in the guest, instead of opening the item's menu and swallowing your next click, and its elapsed time includes any time the Mac slept ([#1583](https://github.com/nicholas-lonsinger/kernova/pull/1583), [#1669](https://github.com/nicholas-lonsinger/kernova/pull/1669), [#1675](https://github.com/nicholas-lonsinger/kernova/pull/1675)).
- **Clipboard transfers no longer stall behind a nested wait.** A clipboard transfer that waited inside another wait could hang; it now goes on at once ([#1648](https://github.com/nicholas-lonsinger/kernova/pull/1648)).

### Drag and drop and file transfer

- **macOS guests: drag files out onto the Mac.** Files and folders dragged from a guest's display to the edge of the Kernova window land wherever you drop them on the Mac, and so do Photos photos, Safari images and Mail attachments, under their real names. The bytes copy when the Mac asks for them, with progress and Cancel; a drag you bring back still drops in the guest. Needs Drag and drop files on ([#1627](https://github.com/nicholas-lonsinger/kernova/pull/1627), [#1682](https://github.com/nicholas-lonsinger/kernova/pull/1682)).
- **macOS guests: dragging photos out is fast.** Dragging photos from a guest's Photos onto the Mac now lands 1,000 photos in about 10 seconds; before, a drag that size failed after a few dozen. Each file reaches the Mac only once it's completely written, and a drag that the guest can't name within 60 seconds is called off cleanly ([#1822](https://github.com/nicholas-lonsinger/kernova/pull/1822)).
- **macOS guests: dropped files land in Downloads and failures say why.** Files dropped on a macOS VM land in the guest's Downloads folder and are shown in Finder, and a drop that fails names the reason, such as Downloads denied or the disk full. Dropping now works for items whose folder Kernova can't open. A drop shows how it ended but no progress while it copies ([#1821](https://github.com/nicholas-lonsinger/kernova/pull/1821)).
- **Copied and dropped files keep what they should.** Duplicate names become `name 2`, as in Finder, including beside a broken symbolic link; read-only folders stay read-only; sparse files stay sparse on another volume; and a file with a resource fork takes the same space as its source ([#1576](https://github.com/nicholas-lonsinger/kernova/pull/1576), [#1683](https://github.com/nicholas-lonsinger/kernova/pull/1683), [#1820](https://github.com/nicholas-lonsinger/kernova/pull/1820)).
- **Folders with unusual contents transfer cleanly or fail by name.** A named pipe, socket or device inside a folder is left out instead of hanging the paste or drag, an item whose path is 1,024 bytes or more or whose name isn't valid UTF-8 is refused before anything is written, and a failure names the item and the reason, such as permission denied ([#1627](https://github.com/nicholas-lonsinger/kernova/pull/1627), [#1673](https://github.com/nicholas-lonsinger/kernova/pull/1673), [#1683](https://github.com/nicholas-lonsinger/kernova/pull/1683)).

### Stop, restart and VM lifecycle

- **macOS guests: Stop and Restart shut macOS down through the agent.** When one user is logged in and their session is on screen or at its lock screen, the agent asks macOS to shut down, and the guest no longer asks "Are you sure you want to shut down?". Apps quit as they do at a restart with "Reopen windows" on.
  At the login window, or with a second user logged in, macOS doesn't shut down for a Stop; use Stop Anyway… or Force Stop… there ([#1814](https://github.com/nicholas-lonsinger/kernova/pull/1814), [#1830](https://github.com/nicholas-lonsinger/kernova/pull/1830), [#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831)).
- **Stop Anyway, Restart Anyway and Force Restart.** On a macOS guest with the agent installed "For everyone", Virtual Machine ▸ Stop Anyway… shuts macOS down without waiting for apps, and apps still open quit without asking to save. Restart Anyway… does the same, then starts the VM again. Force Restart… terminates any VM and starts it again. A restart keeps an Ephemeral VM's session.
  The sidebar menu lists the Anyway commands after Stop and Restart and shows the Force ones while Option is held. The Anyway commands are also optional toolbar items. `kernova stop` and `kernova restart` take `--normal`, `--anyway` or `--force`; AppleScript's `stop` and `restart` take `method normal`, `anyway` or `force`; and the Shortcuts actions offer Normal, Anyway and Force. Each Anyway or Force use asks first ([#1759](https://github.com/nicholas-lonsinger/kernova/issues/1759), [#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831), [#1838](https://github.com/nicholas-lonsinger/kernova/pull/1838)).
- **Restart is everywhere Start and Stop are.** Restart is in the Virtual Machine menu, the sidebar menu and the toolbar, enabled exactly when Stop is, and folder and smart group menus offer Restart All, which restarts every running member at once. `kernova restart --smart-group` or `--folder` and the Shortcuts group action restart a group too ([#1772](https://github.com/nicholas-lonsinger/kernova/pull/1772)).
- **Stop or Force Stop cancels a waiting Restart.** Stopping a VM while a Restart waits for the guest to shut down cancels the Restart quietly, so nothing boots and an Ephemeral VM returns to its baseline ([#1734](https://github.com/nicholas-lonsinger/kernova/pull/1734), [#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831)).
- **Force prompts say what is lost.** Force Stop and Force Restart say that anything in the guest not saved to disk will be lost, in the app, `kernova`, AppleScript and Shortcuts. Force Stop is offered only while the VM can be stopped, not while it's starting, suspending, restoring or taking a live snapshot ([#1324](https://github.com/nicholas-lonsinger/kernova/pull/1324), [#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831)).
- **One alert for VMs that didn't start at launch.** VMs set to Start when Kernova opens that are skipped or fail are listed in a single alert, and the menu bar item reads "N VMs Didn't Start…" ([#1554](https://github.com/nicholas-lonsinger/kernova/pull/1554)).
- **Unattended starts and sleep wait for a busy VM.** The boot after guest setup, a new VM's automatic start, the start at launch and the second half of a Restart wait until the VM is free instead of being skipped. When the Mac sleeps, a VM busy with something like a snapshot pauses once that finishes, and the pause-failed alert no longer warns of data corruption ([#1406](https://github.com/nicholas-lonsinger/kernova/pull/1406), [#1408](https://github.com/nicholas-lonsinger/kernova/pull/1408)).
- **Quitting waits for work in progress and saves every VM it can.** Once Kernova is quitting it waits for snapshot and delete clean-up and saves each running VM in turn, and a VM stuck saving holds back only Kernova's exit, so a force quit costs only that VM ([#1394](https://github.com/nicholas-lonsinger/kernova/pull/1394), [#1491](https://github.com/nicholas-lonsinger/kernova/pull/1491)).
- **Two operations on one VM can no longer collide.** Force Stop during a snapshot revert, and renaming or changing settings during one, are refused as busy ([#1392](https://github.com/nicholas-lonsinger/kernova/pull/1392)).
- **Duplicate machine ID and MAC address checks cover every way a VM comes up.** A revert to a live snapshot, a resume at wake and guest setup are checked like a plain Start instead of running an identical twin ([#1375](https://github.com/nicholas-lonsinger/kernova/pull/1375)).
- **A stale "can't tell whether the guest is shutting down" alert no longer lingers.** It closes when the session it's about ends ([#1814](https://github.com/nicholas-lonsinger/kernova/pull/1814)).

### Networking

- **A guest's IP address is the one the Mac sees.** `kernova ip`, `kernova list`, the Overview, the Network panel, AppleScript and Shortcuts show the address the Mac last saw the guest use, or "Not seen on the network" ([#1335](https://github.com/nicholas-lonsinger/kernova/pull/1335)).
- **Named networks.** Create a NAT or Host Only network in Settings ▸ Networks, with `kernova network create`, or from Shortcuts or AppleScript, then pick it in a VM's network menu or set `network.membership`. Its members reach each other and no other guest.
  Rename one in place in the list, as in the sidebar: click a selected network's name or double-click it; Escape puts the name back, and a refused name stays open to correct. Deleting it from Settings moves its VMs to networks of their own; from a script it's refused until each VM is moved ([#1481](https://github.com/nicholas-lonsinger/kernova/pull/1481), [#1565](https://github.com/nicholas-lonsinger/kernova/pull/1565), [#1947](https://github.com/nicholas-lonsinger/kernova/pull/1947)).
- **Isolate a VM from every other VM.** Turn on "Isolate from other VMs" in the Network panel, or set `network.membership` to `isolated`, to keep a NAT or Host Only guest away from every other VM while it still reaches this Mac ([#1460](https://github.com/nicholas-lonsinger/kernova/pull/1460)).
- **The network menu is grouped by mode.** NAT, Host Only and Bridged head the menu with their common, isolated and named networks under them, and a choice reads like "NAT – Isolated" everywhere ([#1517](https://github.com/nicholas-lonsinger/kernova/pull/1517)).
- **A duplicate MAC address offers a way out.** Starting, resuming, restarting or reverting a VM that shares its MAC address with a running VM offers to start it on a network of its own, with a new MAC address, or with networking off; from a script, the refusal prints these as `kernova` commands. A MAC address a snapshot holds stays reserved to that VM until the snapshot is deleted ([#1367](https://github.com/nicholas-lonsinger/kernova/pull/1367), [#1474](https://github.com/nicholas-lonsinger/kernova/pull/1474), [#1566](https://github.com/nicholas-lonsinger/kernova/pull/1566)).
- **Changing a running VM's network is reliable.** A live network switch can no longer crash or leave the VM's network device detached, and network recovery stops retrying once it has run out of attempts ([#1335](https://github.com/nicholas-lonsinger/kernova/pull/1335), [#1639](https://github.com/nicholas-lonsinger/kernova/pull/1639)).

### Snapshots, clones and Ephemeral Mode

- **Restart keeps an Ephemeral VM's changes.** Restart, from the app or any script, now keeps the guest's changes, as a reboot from inside the guest already did. To return an Ephemeral VM to its baseline, Stop it and Start it again ([#1734](https://github.com/nicholas-lonsinger/kernova/pull/1734)).
- **Live snapshots of a VM writing to a disk outside its bundle are refused.** While a VM has a writable external storage disk or writable removable media, Take Snapshot is available only while it's stopped, because reverting its memory could corrupt that disk. Stop the VM first, or make the disk read-only ([#1477](https://github.com/nicholas-lonsinger/kernova/pull/1477)).
- **Clone as New Machine or Clone as Exact Copy.** A New Machine gets its own machine identity and MAC address and starts with no snapshots and Ephemeral Mode off; an Exact Copy keeps both, with its source's snapshots and Ephemeral Mode, but not Start when Kernova opens. Guests on macOS 12 or earlier can only be cloned as an Exact Copy ([#1417](https://github.com/nicholas-lonsinger/kernova/pull/1417), [#1466](https://github.com/nicholas-lonsinger/kernova/pull/1466), [#1470](https://github.com/nicholas-lonsinger/kernova/pull/1470)).
- **Clone a running, paused or suspended VM.** An Exact Copy carries the saved state and arrives suspended; a New Machine arrives stopped. The source is busy only while its files are copied ([#1400](https://github.com/nicholas-lonsinger/kernova/pull/1400), [#1475](https://github.com/nicholas-lonsinger/kernova/pull/1475)).
- **A create, clone or import in progress is its own sidebar entry.** No VM command reaches it until it's done, a failure names the real file instead of a hidden staging path, and a failure from `kernova clone` or `kernova import --wait` is reported to the command without an alert ([#1385](https://github.com/nicholas-lonsinger/kernova/pull/1385), [#1484](https://github.com/nicholas-lonsinger/kernova/pull/1484)).
- **Snapshots say what they hold.** Each snapshot reads "Running state" or "Powered off", Get Info says it holds disks and settings (plus memory when taken live), and sizes read like "72.4 GB (8.4 GB private)" on volumes that share file data. `kernova snapshot list` shows SIZE and PRIVATE columns ([#1441](https://github.com/nicholas-lonsinger/kernova/pull/1441), [#1442](https://github.com/nicholas-lonsinger/kernova/pull/1442), [#1469](https://github.com/nicholas-lonsinger/kernova/pull/1469)).
- **Suspended VMs record which Kernova version saved them**, and `kernova info` shows it ([#1778](https://github.com/nicholas-lonsinger/kernova/issues/1778)).
- **Turning on Ephemeral Mode takes the baseline for you.** On a VM with no snapshot, the switch opens Take Snapshot and turns the mode on with the new snapshot as its baseline. Turning it on or changing its baseline asks first, and nothing is reverted until the next session ends ([#1479](https://github.com/nicholas-lonsinger/kernova/pull/1479), [#1664](https://github.com/nicholas-lonsinger/kernova/pull/1664)).
- **Deleting the Ephemeral Mode baseline turns Ephemeral Mode off.** Delete… is offered for the baseline in any state, and its confirmation says later power-offs will keep their changes; from a script it's refused until you set `ephemeral=false` ([#1553](https://github.com/nicholas-lonsinger/kernova/pull/1553)).
- **An Ephemeral VM returns to its baseline after Kernova dies mid-session.** After a crash, force quit or power loss, the VM reverts at the next launch instead of booting the unfinished session's changes ([#1664](https://github.com/nicholas-lonsinger/kernova/pull/1664)).
- **Ephemeral VMs say their settings revert.** While a VM's Ephemeral Mode has a baseline, its System, Storage, Network and Sharing settings show a one-line banner saying changes go back at the next shutdown, with an ⓘ that names the baseline and any setting that stays, and Don’t show again. A `kernova` command that changes one of those settings prints the same warning on standard error, naming the VM and its baseline.
  Settings ▸ Reminders turns both off or back on ([#1892](https://github.com/nicholas-lonsinger/kernova/pull/1892)). The Change Virtual Machine Setting action in Shortcuts and the AppleScript dictionary say the same ([#1898](https://github.com/nicholas-lonsinger/kernova/pull/1898)).
- **Saved states are kept safe.** A suspend that fails or is interrupted no longer leaves a half-written saved state, a resumed VM can no longer come back on an older saved state, and a VM holding a saved state stays Suspended with Resume and Discard Saved State when a Start or Resume fails. A resume that fails while the Mac is locked says it needs the Mac unlocked ([#1322](https://github.com/nicholas-lonsinger/kernova/pull/1322), [#1476](https://github.com/nicholas-lonsinger/kernova/pull/1476), [#1666](https://github.com/nicholas-lonsinger/kernova/pull/1666)).
- **Removing missing removable media keeps a suspended VM's session.** When a resume fails on a removable media item, Remove and Resume restores the session without it ([#1478](https://github.com/nicholas-lonsinger/kernova/pull/1478)).
- **A snapshot whose settings can't be read is flagged.** The sidebar and Snapshots card name it, and an Ephemeral VM whose baseline can't be read won't start ([#1544](https://github.com/nicholas-lonsinger/kernova/pull/1544)).
- **One Take Snapshot or Delete sheet per VM.** A second request for the same VM is ignored, another VM's gets its own sheet, and an alert whose question no longer applies, such as Force Stop for a VM that has already stopped, is dropped ([#1585](https://github.com/nicholas-lonsinger/kernova/pull/1585)).

### Sidebar and library

- **Filter, sort and group the sidebar.** The Virtual Machines header's filter menu filters by guest OS, state, network, guest agent, Ephemeral Mode, tag and snapshots, groups by guest OS, state or network, sorts by name, date created, last run or your own order, and shows details such as "Last run 3 hours ago".
  The View menu has the same options, with ⌃⌥⌘1 to 3 and ⌃⌥⌘0 for the sort orders, and the sidebar remembers them across launches ([#1515](https://github.com/nicholas-lonsinger/kernova/pull/1515), [#1518](https://github.com/nicholas-lonsinger/kernova/pull/1518), [#1526](https://github.com/nicholas-lonsinger/kernova/pull/1526), [#1527](https://github.com/nicholas-lonsinger/kernova/pull/1527), [#1529](https://github.com/nicholas-lonsinger/kernova/pull/1529)).
- **Smart groups and folders.** Save a filter as a smart group, or collect VMs in a folder by dragging rows or Finder bundles onto it; both appear as sidebar sections you can reorder and rename in place on their header, and deleting a folder keeps its VMs. New Folder adds an Untitled Folder with its name ready to type, as in the Finder.
  A group's menu offers Start All, Suspend All and Stop All, also from `kernova start|suspend|stop --smart-group|--folder` and Shortcuts, and skips any VM that needs an answer or that another copy of Kernova holds ([#1519](https://github.com/nicholas-lonsinger/kernova/pull/1519), [#1521](https://github.com/nicholas-lonsinger/kernova/pull/1521), [#1523](https://github.com/nicholas-lonsinger/kernova/pull/1523), [#1538](https://github.com/nicholas-lonsinger/kernova/pull/1538), [#1939](https://github.com/nicholas-lonsinger/kernova/pull/1939)).
- **Color tags.** Define tags in Settings ▸ Tags, where a tag is renamed in place as a network is, assign them from a VM's Tags menu, and filter or group by them, also with `kernova list --tag` ([#1524](https://github.com/nicholas-lonsinger/kernova/pull/1524), [#1947](https://github.com/nicholas-lonsinger/kernova/pull/1947)).
- **Search the sidebar.** Edit ▸ Find VM (⌘F) or the Search toolbar button narrows every section by name, and Spotlight and Siri searches fill it in ([#1528](https://github.com/nicholas-lonsinger/kernova/pull/1528)).
- **Unreadable settings files stay visible.** A VM whose settings can't be read is a dimmed sidebar row with a warning instead of a "Failed to load" alert, and File ▸ Check Config Files… lists each problem and repairs what it can, moving each original to the Trash ([#1535](https://github.com/nicholas-lonsinger/kernova/pull/1535)).

### Linux guests

- **Linux guests get a guest agent.** Virtual Machine ▸ Install Guest Agent… attaches an installer disk whose `install.sh` installs Kernova's Linux agent; the Install Guest Agent popover and alert show the command with a Copy button. The VM's agent status, the sidebar badge, scripting and `kernova info` then report it ([#1742](https://github.com/nicholas-lonsinger/kernova/pull/1742), [#1743](https://github.com/nicholas-lonsinger/kernova/pull/1743), [#1748](https://github.com/nicholas-lonsinger/kernova/pull/1748)).
- **Linux guests: choose what to install.** Install Guest Agent… asks whether to install the session agent and system service, the session agent alone, or the system service alone, and copies the matching command ([#1777](https://github.com/nicholas-lonsinger/kernova/issues/1777)).
- **Linux agents update themselves.** An installed agent switches to the version Kernova bundles and relaunches, and goes back to its previous version if the new one never connects; the agent status shows Updating… or Update failed ([#1774](https://github.com/nicholas-lonsinger/kernova/pull/1774)).
- **Forward guest logs from Linux guests.** Settings ▸ Sharing ▸ Forward guest logs, also `agent.logForwarding`, sends the Linux agent's log records to the Mac's log ([#1747](https://github.com/nicholas-lonsinger/kernova/pull/1747)).
- **Every Linux VM gets the socket device the agent needs.** It's added at the VM's next cold boot; a VM resumed from a saved state, snapshot or Ephemeral baseline made before then has none until it next boots from off ([#1744](https://github.com/nicholas-lonsinger/kernova/pull/1744)).
- **Linux guests reconnect at once after a resume.** The agent used to keep one CPU core busy for about 30 seconds and stay disconnected until a timeout; it now reconnects within a second ([#1796](https://github.com/nicholas-lonsinger/kernova/pull/1796)).
- **Linux downloads show the checksum they were checked against.** A VM's General settings list the installer's SHA-256 with a Copy button and what it matched, a pasted URL with no checksum is hashed in a new Checksum step, and a mismatch says what the file failed to match and that a different checksum means creating the VM again ([#1447](https://github.com/nicholas-lonsinger/kernova/pull/1447), [#1456](https://github.com/nicholas-lonsinger/kernova/pull/1456)).
- **Linux clipboard sharing is locked while the VM holds a saved state.** The setting adds a device the saved state lacks, so the Sharing pane and `kernova set` refuse it until the saved state is gone ([#1435](https://github.com/nicholas-lonsinger/kernova/pull/1435)).

### VM creation and macOS guests

- **Create the macOS account during installation.** The New VM wizard's Account step takes the full name, account name, password, automatic login and Remote Login, so a macOS 27 guest's first boot lands at the desktop or login window instead of Setup Assistant. The password is never written to disk; if Kernova needs it again at start it asks in a sheet, where you can also skip the account.
  `kernova start` doesn't take the password, and exits 5 telling you to start the VM in Kernova ([#1238](https://github.com/nicholas-lonsinger/kernova/pull/1238), [#1248](https://github.com/nicholas-lonsinger/kernova/pull/1248), [#1312](https://github.com/nicholas-lonsinger/kernova/pull/1312)).
- **VM limits come from the Virtualization framework.** CPUs run from 1 to 64, memory can be set to the MiB as decimal GB, every disk size is offered for both guests, and a display can be any size. Switching the guest OS in the wizard resets CPU and memory to that guest's defaults ([#1452](https://github.com/nicholas-lonsinger/kernova/pull/1452)).
- **The New VM wizard is quicker to use.** Double-clicking an OS or Download Latest moves to the next step, the download destination is named only once Apple's file name is known, with Try Again if the lookup fails, and VoiceOver reads the current step ([#1463](https://github.com/nicholas-lonsinger/kernova/pull/1463), [#1718](https://github.com/nicholas-lonsinger/kernova/pull/1718), [#1722](https://github.com/nicholas-lonsinger/kernova/pull/1722)).
- **A macOS VM no longer takes a Linux installer or kernel.** Choosing Linux in the New VM wizard, picking an ISO or a kernel, then going back and choosing macOS no longer adds that ISO as a disk, or that kernel, to the new macOS VM ([#1978](https://github.com/nicholas-lonsinger/kernova/pull/1978)).
- **Installer catalogs are current.** The wizard offers macOS 27.2 (26B123) as Apple's current restore image, earlier releases such as 27.0.1 and 27.0, and Kali Linux 2026.3 ([#1494](https://github.com/nicholas-lonsinger/kernova/pull/1494), [#1717](https://github.com/nicholas-lonsinger/kernova/pull/1717)).

### Storage, shared folders and USB

- **Every disk is listed with its size.** The detail header counts a VM's disks, the Overview's Storage card lists each one, and the Storage panel, Boot Order and Get Info show matching sizes; `kernova info` lists every disk, and AppleScript and Shortcuts read them as storage disks ([#1641](https://github.com/nicholas-lonsinger/kernova/pull/1641)).
- **A missing disk or shared folder offers Remove and Start.** When Start or Resume fails because an external disk, removable media item or shared folder is missing or can't be read or written, the alert offers to remove it, or names the Read Only setting. Return no longer presses the destructive button ([#1324](https://github.com/nicholas-lonsinger/kernova/pull/1324), [#1493](https://github.com/nicholas-lonsinger/kernova/pull/1493)).
- **Change a running macOS guest's shared folders.** While at least one share remains, add or remove shares or switch read-only without stopping the VM. Adding the first, removing the last, and any change on a Linux guest still need the VM stopped ([#1453](https://github.com/nicholas-lonsinger/kernova/pull/1453)).
- **macOS 13 guests: shared folders after a resume.** For a guest known to run macOS 13, the Shared Directories info says a shared folder can become unreadable after resuming from Suspend until the guest restarts ([#1486](https://github.com/nicholas-lonsinger/kernova/pull/1486)).
- **Disk and media changes wait their turn.** Creating or removing a disk can no longer overlap a Start, a settings edit or a delete, and attaching or ejecting removable media while the VM is busy with something else happens when that finishes instead of being refused ([#1396](https://github.com/nicholas-lonsinger/kernova/pull/1396), [#1405](https://github.com/nicholas-lonsinger/kernova/pull/1405)).
- **Disk capacities and removals tell the truth.** Removable disks outside the VM show their real capacity, or Unknown when they can't be opened, and a removal that couldn't move a file to the Trash says which file stayed ([#1483](https://github.com/nicholas-lonsinger/kernova/pull/1483), [#1485](https://github.com/nicholas-lonsinger/kernova/pull/1485)).
- **USB accessories go to one VM at a time and wait for a busy VM.** Two VMs can't claim the same accessory, an accessory paired while the VM is busy attaches when it's free, and a live snapshot no longer waits for accessories to come back. On macOS 26, `kernova usb` says USB passthrough needs macOS 27 or later ([#1399](https://github.com/nicholas-lonsinger/kernova/pull/1399), [#1403](https://github.com/nicholas-lonsinger/kernova/pull/1403), [#1407](https://github.com/nicholas-lonsinger/kernova/pull/1407), [#1688](https://github.com/nicholas-lonsinger/kernova/pull/1688)).

### Display and windows

- **⌘F and the clipboard shortcuts reach Kernova first, and customized toolbars need the new buttons.** ⌘F opens Find VM even while a VM's display has the keyboard, unless its System Key Forwarding is Always, and ⌃⇧⌘C and ⌃⇧⌘V run the clipboard commands (Settings ▸ Keyboard gives them back to the guest). A customized toolbar loses its Clipboard item; add Search, Copy to Mac and Copy to Guest with View ▸ Customize Toolbar… ([#1528](https://github.com/nicholas-lonsinger/kernova/pull/1528), [#1819](https://github.com/nicholas-lonsinger/kernova/pull/1819), [#1840](https://github.com/nicholas-lonsinger/kernova/pull/1840)).
- **Starting a VM no longer pulls its display forward.** A display window opens only as Kernova's state suits: none while Kernova lives only in the menu bar, behind other apps while Kernova is in the background, and as before while it's active ([#1242](https://github.com/nicholas-lonsinger/kernova/pull/1242)).
- **A popped-out display stays popped out across a Restart.** The main window no longer draws a second copy of the display, which caused black bars ([#1772](https://github.com/nicholas-lonsinger/kernova/pull/1772)).
- **No "busy starting" alert for a full-screen display.** Starting a VM whose display opens in full screen no longer shows an alert saying the VM is busy starting ([#1849](https://github.com/nicholas-lonsinger/kernova/pull/1849)).
- **Alerts appear on the window you're working in.** An alert about a VM shows on your current window when it can act on that VM, else on the VM's display window, else on the library; alerts with no window to show on wait, and the menu bar item shows "N Alerts Waiting…". Virtual Machine menu commands act on the VM the front window shows, and are disabled when it shows none ([#1585](https://github.com/nicholas-lonsinger/kernova/pull/1585)).
- **Windows stay where you put them.** The Settings window reopens where you moved it after a relaunch, on macOS 26 too and low on the screen. A VM display that reopens straight into full screen returns to its windowed position when you leave full screen, instead of the centre of the screen ([#1962](https://github.com/nicholas-lonsinger/kernova/pull/1962), [#1969](https://github.com/nicholas-lonsinger/kernova/pull/1969)).
- **The main window is titled with the VM's name alone.** The toolbar title no longer starts with "Kernova — ", so a long VM name truncates far less often ([#1886](https://github.com/nicholas-lonsinger/kernova/pull/1886)).
- **Escape closes popovers over a VM's display.** A popover takes the keyboard while open, so typed keys no longer reach the guest ([#1797](https://github.com/nicholas-lonsinger/kernova/pull/1797)).
- **Window and menu bar fixes.** A Dock click restores only a minimized window, Open Kernova from the menu bar or Dock reliably brings it forward, and a pop-out or full-screen VM's menu bar row opens its display whenever there's one to show ([#1316](https://github.com/nicholas-lonsinger/kernova/pull/1316), [#1386](https://github.com/nicholas-lonsinger/kernova/pull/1386), [#1584](https://github.com/nicholas-lonsinger/kernova/pull/1584)).

### Settings

- **Settings edits follow the same rules as `kernova set`.** Every settings pane refuses or asks exactly as the CLI does, a refusal names each setting and the value it was asked to take, and `kernova set` gains audio, input device, serial socket, log forwarding, file drop, start at launch, install reminder and Ephemeral baseline keys ([#1382](https://github.com/nicholas-lonsinger/kernova/pull/1382)).
- **Settings show only what matters, with explanations in ⓘ buttons.** Notes sit with the row they describe, the Settings window sizes to each pane, and value captions sit inside their card ([#1438](https://github.com/nicholas-lonsinger/kernova/pull/1438), [#1469](https://github.com/nicholas-lonsinger/kernova/pull/1469)).
- **A settings value you're still typing is used.** Clicking Start, Clone or any other command while a settings field is still being edited now saves the typed value first. Before, the VM started with the old value and an alert said it was busy ([#1847](https://github.com/nicholas-lonsinger/kernova/pull/1847)).
- **General shows a VM's machine ID.** It appears as a short fingerprint, with a note naming every other VM that shares it ([#1471](https://github.com/nicholas-lonsinger/kernova/pull/1471)).
- **Settings ▸ General always shows the guest's OS version.** Its OS version row reads Unknown until the guest agent reports a version, for Linux VMs too. A macOS VM's install row is now titled "Installed from", so it no longer reads as the version the guest runs today ([#1901](https://github.com/nicholas-lonsinger/kernova/pull/1901)).
- **Duplicate machine IDs: Don't ask again.** With Settings ▸ Advanced ▸ "Offer to start duplicate machine IDs anyway" on, the question now reads "Start “A” with a Duplicate Machine ID?" and offers Don't ask again. Settings ▸ Reminders turns the question off or back on, and its ⓘ shows Apple's warning. While the question is off, the app, `kernova` and start at launch start such a VM without asking.
  With the setting off, the refusal points to Settings ▸ Advanced and has an Open Settings button ([#1831](https://github.com/nicholas-lonsinger/kernova/pull/1831), [#1838](https://github.com/nicholas-lonsinger/kernova/pull/1838)).
- **Each Reminders switch shows its message.** The ⓘ beside each switch in Settings ▸ Reminders shows the reminder's own title and text, then when it appears ([#1887](https://github.com/nicholas-lonsinger/kernova/pull/1887)).
- **The guest agent install reminder can't be changed per VM while it's off for all.** With Settings ▸ Reminders' Guest agent install reminder off, `kernova set <vm> agent.installReminder` and Shortcuts' Set Setting refuse a change and point to Settings ▸ Reminders, as the app's switches already did. In Settings ▸ Reminders, a VM's switch is also unavailable while that VM is starting, suspending or taking a snapshot ([#1894](https://github.com/nicholas-lonsinger/kernova/pull/1894)).
- **Settings wording matches macOS and the app.** "Continue running in the menu bar" replaces Status Bar wording, the Option key captions say what Option reveals, and Ephemeral Mode's text says a revert restores settings as well as disks ([#1341](https://github.com/nicholas-lonsinger/kernova/pull/1341), [#1342](https://github.com/nicholas-lonsinger/kernova/pull/1342), [#1355](https://github.com/nicholas-lonsinger/kernova/pull/1355)).
- **Settings look and update right.** Cards have a visible fill in light and dark appearance, banners and badges follow a Light/Dark switch, info popovers show the current state when opened, and the Shared Directories lock hint appears whenever sharing can't be changed ([#1359](https://github.com/nicholas-lonsinger/kernova/pull/1359), [#1463](https://github.com/nicholas-lonsinger/kernova/pull/1463), [#1490](https://github.com/nicholas-lonsinger/kernova/pull/1490), [#1563](https://github.com/nicholas-lonsinger/kernova/pull/1563)).

### Scripting and Shortcuts

- **Scripts: Kernova comes to the front only when asked.** AppleScript's `start`, `resume` and `restart`, and links, no longer bring Kernova forward; add `activate`, or use `kernova open` or `kernova reveal`, where a script expects to see it ([#1242](https://github.com/nicholas-lonsinger/kernova/pull/1242), [#1381](https://github.com/nicholas-lonsinger/kernova/pull/1381)).
- **Shortcuts actions can consent up front.** Every Shortcuts action that asks before it acts (Start, Stop, Resume, Restart, Delete Virtual Machine, Cancel Virtual Machine Copy, Cancel Guest Setup, Change Virtual Machine Setting, Revert to Snapshot, Delete Snapshot) has a Confirm Before toggle, on by default. Turned off, the action asks nothing, as `kernova --yes` and AppleScript's `with confirmation` do, the duplicate machine ID question included while Settings allows starting one anyway ([#1903](https://github.com/nicholas-lonsinger/kernova/pull/1903)).
- **New Shortcuts action: Change Virtual Machine Setting.** It sets any setting by the key `kernova set` takes and returns the value it ended up with ([#1564](https://github.com/nicholas-lonsinger/kernova/pull/1564)).
- **AppleScript can change a VM's network.** `network mode`, `network membership` and `MAC address` are now writable, and `kernova set <vm> network.mac=new` gives a VM a fresh MAC address ([#1564](https://github.com/nicholas-lonsinger/kernova/pull/1564)).
- **Get Virtual Machine State no longer shows a dialog.** The Shortcuts action returns the state, such as `running`, as before; add Show Result after it to see the state on screen ([#1900](https://github.com/nicholas-lonsinger/kernova/pull/1900)).
- **AppleScript fixes.** `make new virtual machine` is refused instead of crashing, a `set` on several VMs stops at the first refusal and reports it, and a `set` or `delete` that waits on disk sizes runs exactly once ([#1481](https://github.com/nicholas-lonsinger/kernova/pull/1481), [#1564](https://github.com/nicholas-lonsinger/kernova/pull/1564), [#1641](https://github.com/nicholas-lonsinger/kernova/pull/1641)).
- **Spotlight retries a VM it couldn't index** when a VM is added, renamed or removed, or Kernova relaunches ([#1875](https://github.com/nicholas-lonsinger/kernova/pull/1875)).

### CLI

## 0.10.0

The first TestFlight build (build 835, 2026-09-15): everything that changed since the internal 0.9.0 build, from 2026-07-09 to 2026-09-15.

### Action required

- **Re-import your VMs once.** Kernova now runs in the macOS App Sandbox and keeps its library inside its own container, so VMs created with 0.9.0 don't appear after the update. Their bundles are untouched in ~/Library/Application Support/Kernova/VMs: in Finder press Shift-Command-G, open that folder, and drag each `.kernova` bundle onto the Kernova window (or double-click it).
  Importing copies the bundle, so leave room for the copy; once every VM is back and boots, move the old copies to the Trash. If the sidebar order or Always show advanced options comes back at its default, set it again ([#537](https://github.com/nicholas-lonsinger/kernova/pull/537)).
- **Re-choose files that live outside a VM.** The sandbox opens only files you have picked in Kernova, so after re-importing, an external disk image, removable-media image, shared folder, Linux kernel or initrd, or the local IPSW of an unfinished macOS install shows as missing or stops the VM from starting. Open the VM's settings and remove and re-add, or re-choose, each one; disks inside the bundle are unaffected ([#537](https://github.com/nicholas-lonsinger/kernova/pull/537)).
- **Update the guest agent in every macOS guest that has it.** The clipboard and file-transfer protocol changed, so a guest still running the 0.9.0 agent shows that its agent needs updating and has clipboard sharing and drag and drop turned off until it is updated. With the VM running, choose Virtual Machine ▸ Update Guest Agent…, open the disk that appears in the guest, and run `install.command` ([#714](https://github.com/nicholas-lonsinger/kernova/pull/714), [#778](https://github.com/nicholas-lonsinger/kernova/pull/778), [#866](https://github.com/nicholas-lonsinger/kernova/pull/866), [#904](https://github.com/nicholas-lonsinger/kernova/pull/904), [#1106](https://github.com/nicholas-lonsinger/kernova/pull/1106), [#1111](https://github.com/nicholas-lonsinger/kernova/pull/1111)).
- **The serial console socket moved.** An exposed serial socket now lives inside Kernova's container (~/Library/Containers/app.kernova/Data/tmp/) instead of your temporary folder. Point terminal commands and scripts at the path shown beside Expose serial socket in the VM's System settings ([#537](https://github.com/nicholas-lonsinger/kernova/pull/537)).

### Security

- **Kernova runs in the macOS App Sandbox.** It reaches only its own container and the files you pick in an open panel or drag in, and remembers those choices across relaunches ([#537](https://github.com/nicholas-lonsinger/kernova/pull/537)).
- **Guest clipboard content stays on this Mac.** Content copied from a guest is marked for this Mac only, so macOS no longer offers it to nearby devices over Universal Clipboard ([#585](https://github.com/nicholas-lonsinger/kernova/pull/585)).
- **What a guest reports is checked.** Agent and OS version strings from a guest are cut to 64 bytes with control characters removed, so a guest can't flood the settings, the interface or the log, or forge log lines. The log and clipboard channels open only after the guest agent completes its handshake ([#609](https://github.com/nicholas-lonsinger/kernova/pull/609), [#773](https://github.com/nicholas-lonsinger/kernova/pull/773)).

### Snapshots and Ephemeral Mode

- **Multiple named snapshots with revert.** Take any number of named restore points per VM, alongside the single Suspend slot, from the VM's Snapshots settings, the toolbar, or Virtual Machine ▸ Take Snapshot… (Shift-Command-S). Reverting restores the guest and the VM's settings, keeps the snapshot, and resumes a VM that was running; a revert is all-or-nothing even if it fails or Kernova quits partway. The Delete VM sheet lists a VM's snapshots ([#946](https://github.com/nicholas-lonsinger/kernova/pull/946), [#955](https://github.com/nicholas-lonsinger/kernova/pull/955)).
- **Snapshot a VM in any resting state.** A stopped VM takes a disks-only snapshot, and reverting to one leaves the VM stopped. A suspended VM takes a snapshot of its saved session and stays suspended and resumable ([#960](https://github.com/nicholas-lonsinger/kernova/pull/960), [#961](https://github.com/nicholas-lonsinger/kernova/pull/961)).
- **Notes on snapshots.** A note trails each snapshot's name in the Snapshots list and can be edited inline, with Edit Notes, or in Get Info. The Take Snapshot sheet takes multi-line notes: Return adds a line and Command-Return confirms ([#965](https://github.com/nicholas-lonsinger/kernova/pull/965)).
- **Ephemeral Mode returns a VM to a baseline snapshot at power-off.** Turn it on in the VM's Startup settings and pick a baseline. Stopping, force-stopping, or Revert to Baseline on a suspended session returns the VM to the baseline, while suspending keeps the session. The baseline menu labels each snapshot "Memory and disks" or "Disks only", and a caption says whether power-off returns the VM to a suspended session or a stopped one.
  A sidebar badge marks ephemeral VMs, their windows add " (Ephemeral)" to the title while a session runs, and the baseline can't be deleted while the mode is on ([#947](https://github.com/nicholas-lonsinger/kernova/pull/947), [#962](https://github.com/nicholas-lonsinger/kernova/pull/962), [#1187](https://github.com/nicholas-lonsinger/kernova/pull/1187), [#1193](https://github.com/nicholas-lonsinger/kernova/pull/1193)).

### Networking

- **Choose a network mode: Shared Network, Host Only, Bridged or None.** A Mode picker in the VM's Network settings replaces the Networking switch, and existing VMs keep their current setting. Bridged uses a host interface you pick, or Automatic. Host Only lets guests reach the Mac and each other but not your network or the internet ([#824](https://github.com/nicholas-lonsinger/kernova/pull/824), [#828](https://github.com/nicholas-lonsinger/kernova/pull/828)).
- **Switch network mode on a running VM.** Shared Network, Host Only and Bridged can be switched while a VM runs or is paused ([#826](https://github.com/nicholas-lonsinger/kernova/pull/826), [#828](https://github.com/nicholas-lonsinger/kernova/pull/828)).
- **A running VM's network recovers from Wi-Fi and dock changes.** Kernova reattaches the VM's network after the host's link changes; a VM it can't reattach shows a warning tint and tooltip in the sidebar. A bridged VM whose interface is gone still starts and restores, with its network detached ([#826](https://github.com/nicholas-lonsinger/kernova/pull/826)).
- **Each VM's IP address is shown.** Shared Network and Host Only reserve a fixed address per VM, shown with a copy button in the Network settings and the overview even while the VM is stopped; Bridged reads "Assigned by your network" ([#829](https://github.com/nicholas-lonsinger/kernova/pull/829)).
- **Port forwarding.** Add TCP or UDP forwarding rules for Shared Network VMs in the Network settings; a port another VM already uses is refused, and changes apply at the next start. macOS 26 does not forward connections from the Mac's own localhost, as the info popover notes ([#832](https://github.com/nicholas-lonsinger/kernova/pull/832)).
- **Edit or regenerate a VM's MAC address.** The MAC address row is editable, with a Generate button, while the VM is stopped. A MAC another VM already uses is refused with the other VM's name, and two VMs that already share one, for example after an import, show a banner and can't both start ([#833](https://github.com/nicholas-lonsinger/kernova/pull/833), [#840](https://github.com/nicholas-lonsinger/kernova/pull/840), [#844](https://github.com/nicholas-lonsinger/kernova/pull/844)).

### Clipboard

- **The clipboard's File Provider location is gone.** Large clipboard files no longer go through a "Kernova" location in Finder, and there is no longer a File Provider switch to turn on in System Settings; pasting now pulls the data directly. Optional cleanup, on the Mac and in each macOS guest: delete ~/Library/Group Containers/group.app.kernova, and if a Kernova clipboard location still shows in Finder's sidebar, remove it there ([#714](https://github.com/nicholas-lonsinger/kernova/pull/714)).
- **Clipboard pastes now have a size limit.** A copy larger than the maximum paste size, 2 GB unless you change it, is refused whole with an explanation; 0.9.0 had no limit. To move bigger items, raise the limit in Kernova ▸ Settings ▸ Clipboard (up to 16 GB) or use a shared folder ([#714](https://github.com/nicholas-lonsinger/kernova/pull/714), [#745](https://github.com/nicholas-lonsinger/kernova/pull/745)).
- **The clipboard moves data only when you paste.** Copy to Mac and automatic passthrough finish instantly, and the data crosses when something pastes it. Several files and whole folders paste in either direction; folders stream straight into place with no archive file left on disk, and an interrupted transfer removes what it had written ([#593](https://github.com/nicholas-lonsinger/kernova/pull/593), [#601](https://github.com/nicholas-lonsinger/kernova/pull/601), [#714](https://github.com/nicholas-lonsinger/kernova/pull/714), [#778](https://github.com/nicholas-lonsinger/kernova/pull/778), [#866](https://github.com/nicholas-lonsinger/kernova/pull/866)).
- **Choose the maximum paste size.** Kernova ▸ Settings ▸ Clipboard ▸ Maximum paste size offers 512 MB to 16 GB (2 GB recommended), with a caption estimating how long that size takes against the time apps wait for a paste. A larger copy is refused whole, and running guests pick up a change without reconnecting ([#596](https://github.com/nicholas-lonsinger/kernova/pull/596), [#714](https://github.com/nicholas-lonsinger/kernova/pull/714), [#745](https://github.com/nicholas-lonsinger/kernova/pull/745)).
- **Automatic clipboard passthrough (per VM, off by default).** Turn it on in the VM's Sharing settings or with the switch at the bottom of the clipboard window, after a confirmation, and the Mac and the guest share one clipboard, for macOS and Linux guests. While it is on, the clipboard window's manual commands are disabled, and items it couldn't read are reported as skipped ([#557](https://github.com/nicholas-lonsinger/kernova/pull/557), [#610](https://github.com/nicholas-lonsinger/kernova/pull/610), [#749](https://github.com/nicholas-lonsinger/kernova/pull/749), [#752](https://github.com/nicholas-lonsinger/kernova/pull/752), [#989](https://github.com/nicholas-lonsinger/kernova/pull/989)).
- **A redesigned clipboard window.** The contents sit in an inset well with a chip naming their type, and the command bar stays in place ([#989](https://github.com/nicholas-lonsinger/kernova/pull/989)).
- **Transfer progress in the menu bar.** While data crosses, Kernova's status item shows one progress readout per VM for the whole operation and opens on its own during a long paste; the guest agent's status item does the same in the guest ([#650](https://github.com/nicholas-lonsinger/kernova/pull/650), [#654](https://github.com/nicholas-lonsinger/kernova/pull/654), [#714](https://github.com/nicholas-lonsinger/kernova/pull/714)).
- **Refused and partial copies are explained.** A copy that is too large, partly unreadable or failed is reported on the side where you made it: in the clipboard window, or, when it is closed, in a status-item notice that names the VM and opens the clipboard window. The guest agent's menu does the same in the guest ([#714](https://github.com/nicholas-lonsinger/kernova/pull/714), [#782](https://github.com/nicholas-lonsinger/kernova/pull/782), [#893](https://github.com/nicholas-lonsinger/kernova/pull/893), [#1106](https://github.com/nicholas-lonsinger/kernova/pull/1106), [#1111](https://github.com/nicholas-lonsinger/kernova/pull/1111)).
- **Copied files arrive as expected.** Empty files and empty folders now cross the clipboard, a symlink crosses as the contents of its target under the copied name, and an unreadable or vanished file is counted as skipped instead of failing the paste. A guest copy of a deleted file no longer pastes its path as text ([#714](https://github.com/nicholas-lonsinger/kernova/pull/714), [#749](https://github.com/nicholas-lonsinger/kernova/pull/749), [#752](https://github.com/nicholas-lonsinger/kernova/pull/752), [#1106](https://github.com/nicholas-lonsinger/kernova/pull/1106)).
- **A copy with nothing shareable now clears the other side's clipboard.** The previous copy is no longer left pasteable, and the guest agent's menu says the copy carried nothing ([#784](https://github.com/nicholas-lonsinger/kernova/pull/784), [#786](https://github.com/nicholas-lonsinger/kernova/pull/786)).
- **Clipboard pastes no longer stall or freeze Kernova.** Pasting a large guest item keeps the app responsive, with displays drawing and progress climbing; a paste no longer hangs while a menu or sheet is open; and heavy transfers in both directions can no longer wedge the connection or leave a paste waiting on a timeout ([#494](https://github.com/nicholas-lonsinger/kernova/pull/494), [#503](https://github.com/nicholas-lonsinger/kernova/pull/503), [#504](https://github.com/nicholas-lonsinger/kernova/pull/504), [#884](https://github.com/nicholas-lonsinger/kernova/pull/884), [#912](https://github.com/nicholas-lonsinger/kernova/pull/912)).
- **Smaller clipboard fixes.** Cancelling a preview no longer empties or disturbs a paste of the same item, and a preview that fails says why and stops retrying. Host copies made while the guest agent restarts are kept, and a paste cut short by stopping the VM says it didn't finish.
  Progress no longer stops short of 100% when a preview and Copy to Mac overlap, leaving the clipboard window no longer resends unrelated failed copies, turning Clipboard Sharing off on a running VM fully closes it, and the window's title follows VM renames ([#655](https://github.com/nicholas-lonsinger/kernova/pull/655), [#659](https://github.com/nicholas-lonsinger/kernova/pull/659), [#878](https://github.com/nicholas-lonsinger/kernova/pull/878), [#886](https://github.com/nicholas-lonsinger/kernova/pull/886), [#894](https://github.com/nicholas-lonsinger/kernova/pull/894), [#916](https://github.com/nicholas-lonsinger/kernova/pull/916), [#969](https://github.com/nicholas-lonsinger/kernova/pull/969)).

### Drag and drop and file transfer

- **Drag files onto a running macOS VM's display.** Files and folders dropped from Finder land in the guest's Downloads folder, named the way Finder avoids clashes ("name 2.ext"), and are revealed in Finder there when the transfer finishes. Attachments dragged from Photos, Mail and browsers work too. It needs the updated guest agent and works with Clipboard Sharing off ([#855](https://github.com/nicholas-lonsinger/kernova/pull/855), [#933](https://github.com/nicholas-lonsinger/kernova/pull/933)).
- **Drops behave like any other transfer.** A drop queued behind another shows how many are pending, dropping on a paused or stopped VM is refused with the not-allowed cursor, and a drag with some unreadable items sends the rest and reports how many it skipped ([#933](https://github.com/nicholas-lonsinger/kernova/pull/933)).
- **A per-VM Drag and drop files setting.** The VM's Sharing settings have a Drag and drop files switch, on by default, that takes effect at once ([#933](https://github.com/nicholas-lonsinger/kernova/pull/933)).
- **Cancel a transfer from its progress readout.** The progress menu in Kernova's status item and in the guest agent's has a Cancel button for drops and clipboard transfers alike; finished files stay and the partial one is removed ([#855](https://github.com/nicholas-lonsinger/kernova/pull/855)).
- **Locked files arrive unlocked.** Finder-locked files inside a copied or dropped folder now arrive unlocked, so Kernova can always clean up after a transfer ([#868](https://github.com/nicholas-lonsinger/kernova/pull/868)).

### VM creation

- **Restore images always download to your Downloads folder.** The wizard's Change… button for the download location is gone, and each image is saved in Downloads under its version and build. To install from an IPSW kept elsewhere, choose it as a local file in the wizard ([#537](https://github.com/nicholas-lonsinger/kernova/pull/537), [#708](https://github.com/nicholas-lonsinger/kernova/pull/708)).
- **Choose a Version… for macOS guests.** The wizard picks a macOS build from a bundled catalog of Apple restore images, from macOS 12.0.1 through macOS 27.0 (26A428), searchable, with versions this Mac is too old to host dimmed ([#672](https://github.com/nicholas-lonsinger/kernova/pull/672), [#679](https://github.com/nicholas-lonsinger/kernova/pull/679), [#758](https://github.com/nicholas-lonsinger/kernova/pull/758), [#972](https://github.com/nicholas-lonsinger/kernova/pull/972), [#1227](https://github.com/nicholas-lonsinger/kernova/pull/1227)).
- **Paste an IPSW URL… for macOS guests.** Paste an HTTPS link to a restore image; Kernova reads a small part of it to confirm it installs in a VM and shows its version, build and size before downloading ([#672](https://github.com/nicholas-lonsinger/kernova/pull/672)).
- **Download Latest names what it will install.** The wizard and the Review step show the version, build and download size, and the file is saved under its version and build ([#681](https://github.com/nicholas-lonsinger/kernova/pull/681), [#708](https://github.com/nicholas-lonsinger/kernova/pull/708)).
- **Local restore images are checked.** Picking an IPSW, or reusing one already in Downloads, shows its version, build and size; an image for a different build offers Use It Anyway or Download & Replace, and one this Mac can't install blocks Next with the reason ([#672](https://github.com/nicholas-lonsinger/kernova/pull/672), [#983](https://github.com/nicholas-lonsinger/kernova/pull/983), [#985](https://github.com/nicholas-lonsinger/kernova/pull/985)).
- **Choose a Distribution… for Linux guests.** The Linux boot step offers arm64 Ubuntu, Debian, Fedora and Kali installers, including Ubuntu 24.04.5 and 26.04.1 LTS. Kernova downloads the image with resume, verifies its checksum against the distributor's own server, attaches it read-only and boots the installer, and reuses a matching copy already in Downloads instead of downloading it again ([#725](https://github.com/nicholas-lonsinger/kernova/pull/725), [#750](https://github.com/nicholas-lonsinger/kernova/pull/750), [#764](https://github.com/nicholas-lonsinger/kernova/pull/764), [#987](https://github.com/nicholas-lonsinger/kernova/pull/987), [#1227](https://github.com/nicholas-lonsinger/kernova/pull/1227)).
- **Download a Linux installer from any URL.** Image URL… takes a link to an `.iso` and an optional SHA-256; with a checksum the download is verified, and the link must be HTTPS unless a checksum is given ([#743](https://github.com/nicholas-lonsinger/kernova/pull/743)).
- **The New VM wizard closes at once.** The sheet no longer waits for the VM to be written, and a failure is reported afterwards ([#1081](https://github.com/nicholas-lonsinger/kernova/pull/1081)).
- **Download and install fixes.** Download progress no longer jitters; a completed restore-image download no longer fails because its leftover download bundle couldn't be trashed; a download that ran past its expected size no longer blocks setup; an IPSW moved between Start attempts is found again; and cancelling an install or download no longer boots the VM, with cancel dialogs offering Keep Downloading, Keep Installing or Keep Verifying ([#556](https://github.com/nicholas-lonsinger/kernova/pull/556), [#570](https://github.com/nicholas-lonsinger/kernova/pull/570), [#744](https://github.com/nicholas-lonsinger/kernova/pull/744), [#1005](https://github.com/nicholas-lonsinger/kernova/pull/1005), [#1006](https://github.com/nicholas-lonsinger/kernova/pull/1006), [#1084](https://github.com/nicholas-lonsinger/kernova/pull/1084)).
- **Wizard fixes.** Switching from an EFI image to Linux kernel boot no longer leaves the image on the new VM, double-clicking Create no longer makes two VMs, and a VM whose creation failed no longer reappears as a broken VM ([#743](https://github.com/nicholas-lonsinger/kernova/pull/743), [#1081](https://github.com/nicholas-lonsinger/kernova/pull/1081), [#1092](https://github.com/nicholas-lonsinger/kernova/pull/1092)).

### Display and input

- **Closing a pop-out or full-screen display no longer returns it to the library window.** The window closes and the VM keeps running without a visible display. Use Show Display or the status item to bring the window back, or Pop In to show the display in the library window again ([#632](https://github.com/nicholas-lonsinger/kernova/pull/632)).
- **Per-VM display settings.** Size to fit the window at startup (on by default) boots the VM at the size of the pane, pop-out window or full-screen screen. Resolution presets, a custom size, a HiDPI switch for macOS guests, and Automatically resize with window, which can be toggled while the VM runs, are also available ([#690](https://github.com/nicholas-lonsinger/kernova/pull/690)).
- **Show Display and a Display Closed placeholder.** The placeholders for a popped-out or full-screen VM have a Show Display button, and a closed display shows Display Closed with Show Display and Pop In ([#632](https://github.com/nicholas-lonsinger/kernova/pull/632)).
- **Choose when system keys reach the guest.** A per-VM Send system keys to guest setting (Never, In Full Screen, Always) in the System settings applies at once to macOS and Linux guests; Always matches earlier behavior ([#1190](https://github.com/nicholas-lonsinger/kernova/pull/1190)).
- **Choose a macOS guest's keyboard and pointer.** macOS guests get exactly one keyboard and pointing device: the Mac keyboard and trackpad for macOS 13 and later, and USB keyboard and mouse for older guests, which fixes input on macOS 12 and stops newer guests from showing scroll bars all the time. A new Input devices setting can choose either explicitly ([#683](https://github.com/nicholas-lonsinger/kernova/pull/683), [#827](https://github.com/nicholas-lonsinger/kernova/pull/827)).
- **Keyboard focus follows the VM display.** After you start, resume or Pop In a VM, typing reaches the guest without an extra click, unless you have since moved elsewhere ([#712](https://github.com/nicholas-lonsinger/kernova/pull/712)).
- **Display fixes.** Clicking a VM in the status menu opens only its own pop-out or full-screen window, a pop-out's title follows a rename, and starting a VM no longer brings Kernova in front of other apps ([#631](https://github.com/nicholas-lonsinger/kernova/pull/631), [#962](https://github.com/nicholas-lonsinger/kernova/pull/962), [#1233](https://github.com/nicholas-lonsinger/kernova/pull/1233)).

### Guest agent

- **The guest agent runs on macOS 12 and later.** Every macOS version the restore-image catalog offers can run the agent. Guests older than 12.3, which can't read the installer as a USB disk, get it as a read-only disk at every boot, and Install Guest Agent… says where it is ([#747](https://github.com/nicholas-lonsinger/kernova/pull/747), [#768](https://github.com/nicholas-lonsinger/kernova/pull/768)).
- **A safer installer.** The new agent is checked before the old one stops and is rolled back if the swap fails; `install.command` and `uninstall.command` accept `-y` or `--yes` to run without prompts, and the scripts are no longer copied into every guest ([#622](https://github.com/nicholas-lonsinger/kernova/pull/622), [#731](https://github.com/nicholas-lonsinger/kernova/pull/731)).
- **VM settings show what a guest runs.** Installed Version shows the macOS build a VM was installed from (Installer Image for Linux), and OS Version shows the version the guest agent reports, in the same form in every language; each row is hidden when unknown ([#687](https://github.com/nicholas-lonsinger/kernova/pull/687), [#689](https://github.com/nicholas-lonsinger/kernova/pull/689), [#696](https://github.com/nicholas-lonsinger/kernova/pull/696), [#763](https://github.com/nicholas-lonsinger/kernova/pull/763), [#768](https://github.com/nicholas-lonsinger/kernova/pull/768)).
- **Agent status is accurate.** The guest-agent badge shows only while the VM runs, an agent that quits mid-session shows as missing instead of spinning forever, a silent one drops back to Connecting instead of staying Unresponsive, and clipboard and log channels connect right after the agent does instead of seconds later ([#625](https://github.com/nicholas-lonsinger/kernova/pull/625), [#707](https://github.com/nicholas-lonsinger/kernova/pull/707), [#710](https://github.com/nicholas-lonsinger/kernova/pull/710), [#771](https://github.com/nicholas-lonsinger/kernova/pull/771)).
- **Guest agent fixes.** Guest log records from the agent's first moments after install or boot are kept, no log record arrives after forwarding stops, and Guest Agent Disk is offered only to macOS guests ([#620](https://github.com/nicholas-lonsinger/kernova/pull/620), [#773](https://github.com/nicholas-lonsinger/kernova/pull/773), [#1208](https://github.com/nicholas-lonsinger/kernova/pull/1208)).

### Shortcuts, Spotlight and AppleScript

- **Drive VMs from Shortcuts and Spotlight.** Actions list VMs and get their details and IP address; start, stop, pause, resume, suspend, restart and open them; take, revert, rename, annotate and delete snapshots; clone, rename, import and delete VMs (delete moves to the Trash); cancel a clone or setup; and quit Kernova. A destructive stop asks first, and Find Virtual Machine filters and sorts by name, state, guest OS and more ([#1008](https://github.com/nicholas-lonsinger/kernova/pull/1008), [#1011](https://github.com/nicholas-lonsinger/kernova/pull/1011), [#1151](https://github.com/nicholas-lonsinger/kernova/pull/1151), [#1162](https://github.com/nicholas-lonsinger/kernova/pull/1162)).
- **VMs in Spotlight.** VMs are indexed by name, and choosing one brings its display or library row forward; Siri's typed search matches VM names too ([#1124](https://github.com/nicholas-lonsinger/kernova/pull/1124), [#1135](https://github.com/nicholas-lonsinger/kernova/pull/1135)).
- **Kernova is scriptable with AppleScript.** Script Editor, Automator and `osascript` can read every VM's properties and `start`, `stop`, `restart`, `pause`, `resume`, `suspend` or `reveal` it. A destructive stop needs `with confirmation`, and `giving up after` sets a stop timeout ([#1179](https://github.com/nicholas-lonsinger/kernova/pull/1179)).
- **`kernova://` links.** `kernova://open/<vm>` brings a VM's display forward and `kernova://reveal/<vm>` selects it in the library, by name or identifier ([#1170](https://github.com/nicholas-lonsinger/kernova/pull/1170)).
- **Names match regardless of case.** Shortcuts, AppleScript, links and the command-line tool find "Sonoma" from "sonoma"; two names that differ only by case are refused as ambiguous ([#1181](https://github.com/nicholas-lonsinger/kernova/pull/1181)).
- **Automation launches stay in the background.** When a shortcut or the command-line tool launches Kernova, it starts without a window and stays running, in the status item or hidden with its Dock icon, until it is quit; VMs marked to start when Kernova opens still start ([#1151](https://github.com/nicholas-lonsinger/kernova/pull/1151)).

### Command-line tool

- **The `kernova` command-line tool.** Bundled with the app and installed from Kernova ▸ Settings ▸ Advanced, it runs `list`, `info`, `ip`, `start`, `stop`, `suspend`, `pause`, `resume`, `restart`, `open`, `wait`, `quit` and `version`, with table or JSON output and defined exit codes. It launches Kernova hidden when it isn't running, and `stop` and `restart` take `--timeout <seconds>` ([#1144](https://github.com/nicholas-lonsinger/kernova/pull/1144), [#1151](https://github.com/nicholas-lonsinger/kernova/pull/1151), [#1160](https://github.com/nicholas-lonsinger/kernova/pull/1160)).
- **Manage the library from the command line.** `snapshot list|take|revert|delete|rename`, `clone`, `import`, `rename`, `delete` and `reveal`; `clone` and `import` wait for the copy unless given `--no-wait` ([#1162](https://github.com/nicholas-lonsinger/kernova/pull/1162)).
- **Read and change VM settings.** `kernova get` and `kernova set` cover CPUs, memory, display, input, network, Ephemeral Mode and clipboard settings (`get --keys` lists them), with the same limits as the settings pane; turning on clipboard passthrough needs `--yes` ([#1164](https://github.com/nicholas-lonsinger/kernova/pull/1164), [#1190](https://github.com/nicholas-lonsinger/kernova/pull/1190)).
- **Shared folders and port forwards.** `kernova share list|add|remove` and `kernova forward list|add|remove` edit a VM's shared folders and forwarded ports ([#1164](https://github.com/nicholas-lonsinger/kernova/pull/1164), [#1176](https://github.com/nicholas-lonsinger/kernova/pull/1176)).
- **Shell completion.** Tab completes VM names, snapshot names and setting keys for zsh, bash and fish, installed from Kernova ▸ Settings ▸ Advanced ([#1171](https://github.com/nicholas-lonsinger/kernova/pull/1171)).

### Storage, shared folders and USB

- **USB accessory passthrough (macOS 27).** Accessories you assign to Kernova in macOS's Virtual Machine Accessories menu extra can be attached to a running VM from its USB Device menu or with `kernova usb attach`. Kernova remembers which VM an accessory went to and passes it through again when both are available; the VM's Sharing settings and `kernova usb rules` / `usb forget` list and remove those pairings ([#1215](https://github.com/nicholas-lonsinger/kernova/pull/1215), [#1221](https://github.com/nicholas-lonsinger/kernova/pull/1221)).
- **Notes on disks and removable media.** Each row shows a free-form note after its name, editable inline, with Edit Notes, or in Get Info ([#968](https://github.com/nicholas-lonsinger/kernova/pull/968)).
- **A missing attachment is a recoverable start failure.** If a disk, ISO or installer can't be opened, the alert names it and offers Remove and Start, which detaches it without touching the file and starts the VM ([#627](https://github.com/nicholas-lonsinger/kernova/pull/627)).
- **Settings say why storage is locked.** Storage Disks read "Editable when stopped" and Removable Media "Editable when stopped or running", and shared folders follow the same rules as disks ([#1086](https://github.com/nicholas-lonsinger/kernova/pull/1086), [#1112](https://github.com/nicholas-lonsinger/kernova/pull/1112)).
- **`serial.log` stays small.** A VM's console log is capped at 10 MB and rolls over to `serial.log.1` ([#848](https://github.com/nicholas-lonsinger/kernova/pull/848)).
- **Missing files are flagged sooner.** Kernova re-checks disks, removable media and shared folders when it becomes active and when settings open, and a missing shared folder is flagged like a missing disk ([#1108](https://github.com/nicholas-lonsinger/kernova/pull/1108), [#1113](https://github.com/nicholas-lonsinger/kernova/pull/1113)).
- **Storage fixes.** Removing a VM's only disk is refused, while a VM with two disks can remove Disk.asif again; ejecting media just before Suspend now saves without it; media changes while a VM saves are refused instead of silently not applied; a media change from before a force-stop no longer affects the restarted VM; and an empty disk list in a hand-edited configuration means the main disk ([#1065](https://github.com/nicholas-lonsinger/kernova/pull/1065), [#1083](https://github.com/nicholas-lonsinger/kernova/pull/1083), [#1092](https://github.com/nicholas-lonsinger/kernova/pull/1092), [#1094](https://github.com/nicholas-lonsinger/kernova/pull/1094), [#1096](https://github.com/nicholas-lonsinger/kernova/pull/1096), [#1099](https://github.com/nicholas-lonsinger/kernova/pull/1099)).

### Library: import, clone and delete

- **Imports and clones copy in parallel.** Each dropped bundle gets its name immediately and copies alongside the others, cancelling one no longer holds up the rest, and a VM can be cloned while a different VM is copying ([#494](https://github.com/nicholas-lonsinger/kernova/pull/494), [#1049](https://github.com/nicholas-lonsinger/kernova/pull/1049)).
- **Choose whether clones keep the machine ID.** Clones get a new machine ID by default; turning that off keeps the source's, which macOS 12 and earlier guests need. A second Clone command in the Virtual Machine menu, and as an Option alternate in the sidebar, does the opposite ([#698](https://github.com/nicholas-lonsinger/kernova/pull/698)).
- **Delete a suspended VM directly.** Move to Trash and Delete Immediately work on a suspended VM without discarding its saved state first, and the delete sheet lists the saved state. A Linux VM's kernel and initrd can be trashed with it, unchecked by default ([#774](https://github.com/nicholas-lonsinger/kernova/pull/774), [#1084](https://github.com/nicholas-lonsinger/kernova/pull/1084)).
- **No more half-made VMs.** Create, clone and import build the bundle out of sight and add it to the library only when complete, and anything left by a crash is cleaned up at the next launch ([#1088](https://github.com/nicholas-lonsinger/kernova/pull/1088)).
- **Delete is safer.** Confirming a delete after the VM has started no longer trashes the running VM, a file another VM still uses is never trashed even after a move, and Move to Trash is disabled while a VM is importing or cloning ([#774](https://github.com/nicholas-lonsinger/kernova/pull/774), [#1089](https://github.com/nicholas-lonsinger/kernova/pull/1089)).
- **Clone and import fixes.** A VM being cloned can't be started, deleted, reverted or have its disks changed until the copy finishes, a VM still copying can't be renamed, its sidebar row updates once it is ready, and a clone no longer inherits a dismissed guest-agent reminder ([#563](https://github.com/nicholas-lonsinger/kernova/pull/563), [#580](https://github.com/nicholas-lonsinger/kernova/pull/580), [#1004](https://github.com/nicholas-lonsinger/kernova/pull/1004), [#1100](https://github.com/nicholas-lonsinger/kernova/pull/1100)).

## 0.9.0

Internal distribution only (2026-03-27 to 2026-07-09). Changes since 0.1.

### Action required

- **Suspended VMs may not resume after the update.** Every macOS VM gains a new guest-agent device, and VMs with a disc image or extra disks attach them differently, so a VM suspended under 0.1 may fail to restore; Kernova then discards the saved state and starts the VM fresh, losing whatever was unsaved in the guest. Before updating, resume each suspended VM and shut it down from inside the guest ([#143](https://github.com/nicholas-lonsinger/kernova/pull/143), [#220](https://github.com/nicholas-lonsinger/kernova/pull/220)).
- **Extra disks and attached disc images are not carried over.** The disc-image and additional-disk settings were replaced by the Storage Disks and Removable Media lists, and nothing reads the old entries: a VM keeps only its main disk, comes up with no disc image, and forgets its read-only and boot-from-disc choices.
  Before updating, note each VM's extra disks and disc image (internal extra disks stay in the bundle's AdditionalDisks folder); afterwards re-add them under Storage Disks or Removable Media in the VM's Settings and set read-only and boot order again. The Window ▸ Removable Media popover (⇧⌘U) is gone too; use the Removable Media section of the VM's Settings ([#220](https://github.com/nicholas-lonsinger/kernova/pull/220)).
- **Microphone access resets to off.** The Microphone setting is now Audio Input and was not migrated. Turn Audio Input back on in each VM's Settings ▸ Audio that needs it ([#304](https://github.com/nicholas-lonsinger/kernova/pull/304)).
- **New app identifier: preferences and microphone permission start over.** Kernova's identifier changed from `com.kernova.app` to `app.kernova`, so the custom sidebar order and last selected VM reset, macOS asks for microphone permission again once, and Console.app logs move to the `app.kernova` subsystem. Re-arrange the sidebar and allow microphone access when asked; existing `.kernova` bundles open as before ([#328](https://github.com/nicholas-lonsinger/kernova/pull/328)).
- **macOS guests need the Kernova guest agent for clipboard sharing.** macOS guests no longer get the SPICE clipboard port, so a third-party SPICE agent (such as UTM's or Tart's) stops syncing the clipboard. Install the Kernova guest agent with Virtual Machine ▸ Install Guest Agent…. Linux guests keep using `spice-vdagent` and need nothing ([#148](https://github.com/nicholas-lonsinger/kernova/pull/148)).

### Clipboard

- **macOS guests: copy text, images, files and folders both ways.** With the guest agent installed, the clipboard carries plain and styled text (including inline images), images, one or several files, and folders or packages such as .app between the Mac and a macOS guest in both directions; same-named files get distinct names. It runs over a dedicated channel that survives suspend and restore ([#127](https://github.com/nicholas-lonsinger/kernova/pull/127), [#148](https://github.com/nicholas-lonsinger/kernova/pull/148), [#343](https://github.com/nicholas-lonsinger/kernova/pull/343), [#359](https://github.com/nicholas-lonsinger/kernova/pull/359), [#368](https://github.com/nicholas-lonsinger/kernova/pull/368), [#369](https://github.com/nicholas-lonsinger/kernova/pull/369)).
- **Transfers are lazy and have no size limit.** A copy sends only a description; the bytes cross when you paste in the guest or paste after Copy to Mac on the host, so a paste can come long after the copy, even after the clipboard window has closed or the VM has stopped.
  Files stream to disk, so multi-gigabyte copies work in both directions, bounded only by free disk space, and disk-full or timeout failures are reported in the clipboard window ([#352](https://github.com/nicholas-lonsinger/kernova/pull/352), [#356](https://github.com/nicholas-lonsinger/kernova/pull/356), [#372](https://github.com/nicholas-lonsinger/kernova/pull/372), [#402](https://github.com/nicholas-lonsinger/kernova/pull/402), [#408](https://github.com/nicholas-lonsinger/kernova/pull/408)).
- **Large files paste through Finder without timing out.** Pasting a large file into a macOS guest returns at once and the file arrives as it is read, once the guest's Kernova File Provider extension is enabled in its System Settings (the agent's menu links there).
  Copy to Mac of a single guest file puts a placeholder on the Mac pasteboard and fetches the bytes on paste; until the File Provider is enabled on the Mac, a banner in the clipboard window links to System Settings and pastes fall back to a copy capped at about 256 MiB. Cancelling a paste in Finder stops the transfer ([#425](https://github.com/nicholas-lonsinger/kernova/pull/425), [#434](https://github.com/nicholas-lonsinger/kernova/pull/434), [#447](https://github.com/nicholas-lonsinger/kernova/pull/447), [#462](https://github.com/nicholas-lonsinger/kernova/pull/462), [#495](https://github.com/nicholas-lonsinger/kernova/pull/495)).
- **Live transfer progress.** Large Copy to Mac and paste transfers fill a progress bar at the bottom of the clipboard window and a thin bar under the toolbar's Clipboard button; quick transfers never flash one ([#417](https://github.com/nicholas-lonsinger/kernova/pull/417)).
- **Clipboard window rebuilt.** It previews small items and shows image files as images, accepts drag and drop anywhere in the window, and has Paste from Mac and Copy to Mac buttons ([#343](https://github.com/nicholas-lonsinger/kernova/pull/343), [#356](https://github.com/nicholas-lonsinger/kernova/pull/356)).
- **Clipboard privacy markers are respected.** Items marked transient or auto-generated never sync; password-manager items still sync for pasting but show a lock placeholder in the clipboard window instead of a preview ([#388](https://github.com/nicholas-lonsinger/kernova/pull/388)).
- **The clipboard window no longer opens collapsed.** It opens at a usable size and remembers its size and position ([#124](https://github.com/nicholas-lonsinger/kernova/pull/124), [#128](https://github.com/nicholas-lonsinger/kernova/pull/128)).
- **Linux guests: the clipboard no longer shows as disconnected while a VM is paused.** Disconnects are now detected only from real connection failures ([#142](https://github.com/nicholas-lonsinger/kernova/pull/142)).

### App

- **VMs keep running when you close Kernova's windows.** Kernova is a resident menu-bar app: closing its windows or pressing ⌘Q leaves running VMs executing in the background, with a menu-bar item offering Open Kernova, the running VMs and Quit Kernova, which suspends running VMs and exits. ### VM creation

- **A native Mac app for macOS and Linux virtual machines.** Kernova runs VMs on Apple's Virtualization framework on macOS 26, from a window with a library sidebar, a creation wizard and per-VM settings. Start one with File ▸ New Virtual Machine… (Cmd+N) or the New VM button ([97426151c](https://github.com/nicholas-lonsinger/kernova/commit/97426151c31009ae2f71fc64d86892368e931bbf)).
- **A step-by-step creation wizard.** Pick macOS or Linux, choose the install source, then set the name, CPUs, memory, disk size and whether the VM has networking, and confirm on a review step. A hint beside the Next button says what each step still needs ([97426151c](https://github.com/nicholas-lonsinger/kernova/commit/97426151c31009ae2f71fc64d86892368e931bbf), [6589cdc40](https://github.com/nicholas-lonsinger/kernova/commit/6589cdc40631df8b85408b90415ad1e5144403fb), [6bec323c2](https://github.com/nicholas-lonsinger/kernova/commit/6bec323c22418a4ee3effde61da9ca129d95fb89)).
- **Clone a stopped VM.** Virtual Machine ▸ Clone (Cmd+D) or the context menu copies the disk and configuration under a new identity, with "Copy" added to the name ([e7b7310c0](https://github.com/nicholas-lonsinger/kernova/commit/e7b7310c0ac4e19458bd40ee1729efed2cc35b05)).
- **Clone and import run in the background with progress.** A sidebar row with a spinner appears at once and the detail pane shows progress; you can cancel with confirmation, and partially copied files are removed. One clone or import runs at a time ([#15](https://github.com/nicholas-lonsinger/kernova/pull/15)).

### macOS guests

- **Install macOS from the latest restore image or your own IPSW.** Download Latest fetches the newest compatible restore image from Apple to a location you choose (Downloads by default), and the file stays separate from the VM so you can reuse it; Choose Local File uses an IPSW already on your Mac. If a file already exists at the download location, you pick Use Existing File or Download & Replace before continuing ([bca872d81](https://github.com/nicholas-lonsinger/kernova/commit/bca872d81e3f17bcb6f21d1289807cd177e77073), [d07d91ab1](https://github.com/nicholas-lonsinger/kernova/commit/d07d91ab1187b93488dabfcd798c223a9ee16270)).
- **The restore image downloads in place.** The file appears in Finder at the chosen location and grows as it downloads; cancelling deletes the partial file ([05812e96d](https://github.com/nicholas-lonsinger/kernova/commit/05812e96dfb297118a2f2c5a914e413bbc74f810)).
- **Installation progress in two steps.** Download and Install appear as numbered steps with their own progress bars; the download line shows size to three decimal places, a smoothed speed and the time remaining, in steady fixed-width digits. A local restore image shows a single Install bar ([9951f6de3](https://github.com/nicholas-lonsinger/kernova/commit/9951f6de3932928fde2ac122095618c789a97a48), [d7d1acba3](https://github.com/nicholas-lonsinger/kernova/commit/d7d1acba3cc0e2238d48123caeb181852ec9135b), [#114](https://github.com/nicholas-lonsinger/kernova/pull/114), [#118](https://github.com/nicholas-lonsinger/kernova/pull/118)).
- **Cancel an installation.** A Cancel button, with confirmation, stops the download or install and moves the half-created VM to the Trash ([36b2f869d](https://github.com/nicholas-lonsinger/kernova/commit/36b2f869dc7f44906a29ff52e73cb8c661480b03)).

### Linux guests

### Running VMs

- **Start, pause, resume and stop from the menu, toolbar or sidebar.** Double-click a VM in the sidebar to start or resume it. Stop asks the guest to shut down; Virtual Machine ▸ Force Stop or the context menu ends an unresponsive VM after a confirmation that also offers Shut Down ([5d4e53301](https://github.com/nicholas-lonsinger/kernova/commit/5d4e53301ab5ce0468128ae260dd10c2fb3a310e), [550ed45ca](https://github.com/nicholas-lonsinger/kernova/commit/550ed45ca43c402ff17492159f4bdd6d2560f73b), [#16](https://github.com/nicholas-lonsinger/kernova/pull/16), [27b15b471](https://github.com/nicholas-lonsinger/kernova/commit/27b15b471323d23eba3e9d40662624df926aaf84)).
- **Suspend saves a VM's state to disk.** Virtual Machine ▸ Suspend (Cmd+Opt+S) saves the running VM and frees its resources; it resumes where it left off, including after you quit and relaunch Kernova, and cold boots if the saved state can't be restored. The sidebar shows Suspended with an orange dot and Paused with a yellow one, with a tooltip explaining each.
  Stopping a suspended VM asks before discarding its saved state, and the context menu shows Discard Saved State ([6c0b3bfca](https://github.com/nicholas-lonsinger/kernova/commit/6c0b3bfcad6f0b4cc75df78b6e39973b6964ca26), [37c0603ad](https://github.com/nicholas-lonsinger/kernova/commit/37c0603ad91fbe7b9a126f18cb574d918dff7c55), [5ccc2f320](https://github.com/nicholas-lonsinger/kernova/commit/5ccc2f320749a2b2d6b9e764a2c400beb041b40f), [29c962dff](https://github.com/nicholas-lonsinger/kernova/commit/29c962dff877d6a906b71e6602b143587d741023), [#42](https://github.com/nicholas-lonsinger/kernova/pull/42)).
- **VMs pause when the Mac sleeps.** Running VMs pause on sleep and resume on wake; a VM you paused yourself stays paused ([a42a604d3](https://github.com/nicholas-lonsinger/kernova/commit/a42a604d3c3ef1536b0c3fee5e0689d17919d536)).
- **Missing files are caught before launch.** A missing kernel, initrd, disc image or shared folder, including one behind a broken symlink, or a shared folder that isn't a readable (or writable) directory, stops the start with an error naming the problem ([4c65b1e4d](https://github.com/nicholas-lonsinger/kernova/commit/4c65b1e4da8f560cad38dede169ce036cf46e802), [#14](https://github.com/nicholas-lonsinger/kernova/pull/14)).
- **Kernova relaunches itself when macOS revokes a permission.** Changing Kernova's microphone access in System Settings while VMs run suspends them and relaunches the app; a normal quit does not relaunch ([#105](https://github.com/nicholas-lonsinger/kernova/pull/105)).
- **Serial console.** Window ▸ Serial Console (Cmd+Shift+T) opens a terminal for a running VM that sends your keystrokes to the guest, shows its output, and can save the output to disk. The window closes when the VM stops, and the command is unavailable while no VM runs ([fe0c156b2](https://github.com/nicholas-lonsinger/kernova/commit/fe0c156b2238e015f313f25f7c944d814bcf8b76), [#8](https://github.com/nicholas-lonsinger/kernova/pull/8), [#10](https://github.com/nicholas-lonsinger/kernova/pull/10)).

### Display

### Storage

- **Each VM is a single .kernova package.** Finder treats a VM as one file. Double-click a .kernova file or drag it onto the sidebar to add it to the library, and use Show in Finder in the context menu to reveal it ([cd5a86c64](https://github.com/nicholas-lonsinger/kernova/commit/cd5a86c64d0e5133a5984aa1f4ac7adbabe6fcf7), [c3c9f8eea](https://github.com/nicholas-lonsinger/kernova/commit/c3c9f8eea1a661bf9bd988e3f6ad10a1fcee6b85)).

- **Removable media.** Settings ▸ Removable Media attaches a disc image (an installer ISO or another image) as a USB drive, optionally read-only, and EFI VMs can boot from it. While a VM runs, the toolbar's Removable Media button or Window ▸ Removable Media (Cmd+Shift+U) attaches and ejects further images; these are ejected when the VM stops ([8554d659b](https://github.com/nicholas-lonsinger/kernova/commit/8554d659be9aedca13436cddbd8c1e739c832f55), [#83](https://github.com/nicholas-lonsinger/kernova/pull/83)).
